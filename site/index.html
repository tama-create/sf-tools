🚀 sf-tools

Salesforce の変更を、安全に、決まった手順で、本番に届けるための道具です。

「変更を作る → 確かめる → 本番に反映する」という毎日のくり返しを、コマンドと自動の仕組みに任せられます。変更は、本番に出る前に、自動でチェックされます。うっかりミスや、反映のし忘れを防げます。

  • 🔑 最初の準備は、プロジェクト管理者が、1 回だけ行います。
  • 💻 毎日の作業で使うのは、おもに開発者です。
  • 👀 業務担当の方が、コマンドを使う必要は、ほとんどありません。Slack に届く結果の通知を見る形で、関わります。

しくみは、シェルスクリプト（コマンド）の集まりです。パソコンの ~/sf-tools に置いて、各プロジェクトのフォルダから呼び出します。変更の検証とリリースは、GitHub Actions（GitHub 上の自動処理）が行います。

まず、全体の流れ

順番が決まっています。管理者の準備が先です

sf-tools は、管理者が、sf-tools の雛形で作った、決まった形のリポジトリ（force-XXXX）の上でしか動きません。そのため、最初に、管理者が、リポジトリを作ります。開発者は、それが終わってから始めます。同時には進められません。

最短で試す

先に、管理者がプロジェクトを作っている必要があります

プロジェクト（force-XXXX）は、管理者が先に作ります（管理者ガイド）。管理者から「できました」と連絡を受けて、リポジトリの名前を聞いてから、始めてください。まだないうちは、下の手順は動きません。必要なツール（Git・Salesforce CLI など）も、あらかじめ入れておきます（前提条件とインストール）。

  1. sf-tools をパソコンに置いて、どこからでも使えるようにします（最初の 1 回だけです）。

    git clone https://github.com/tama-create/sf-tools.git ~/sf-tools
echo 'export PATH="$HOME/sf-tools/bin:$PATH"' >> ~/.bashrc    # Mac は ~/.zshrc

    そのあと、ターミナルを開き直します。

  2. プロジェクトの作業フォルダで、新しい作業を始めます。ブランチの名前を入力すると、作業用のコピーの準備から、VS Code の起動までが進みます。

    sf-job.sh

  3. 作業を始めると、VS Code が開き、ターミナルにはランチャー（メニュー）が自動で開きます。変更を書いたら、ランチャーの番号を押して進めます（[1] で確認、[2] で変更を送る）。コマンドを覚える必要は、ありません。

      [1] Check      ターゲットファイルの構文チェック
  [2] Push       変更をコミット & プッシュ
  [3] Next       次の PR 先ブランチを確認
  ……

    コマンドに慣れている方は、sf-push.sh のように、直接打つこともできます。メニューを出し直したいときは、sf-launcher.sh と打ちます（くわしくは日々の開発の流れ）。

Windows と Mac で動きます

Windows は Git Bash、Mac は標準のターミナルで使えます。確かめた環境の一覧は、動作環境にあります。
