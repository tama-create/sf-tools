📝 ターゲットファイルの書き方

「何を反映するか」と「何を削除するか」を、2 つのファイルに書いておきます。ファイルは、force-XXXX フォルダの中の sf-tools/release/<ブランチ名>/ に置きます（パソコンに置いた ~/sf-tools とは、別のフォルダです）。ブランチ名は、sf-job.sh で作った作業の名前です。

ファイル役割
deploy-target.txtデプロイするメタデータを列挙する
remove-target.txt削除するメタデータを列挙する

deploy-target.txt

[files]
# ファイルパスで指定
force-app/main/default/classes/MyController.cls
force-app/main/default/classes/MyControllerTest.cls
force-app/main/default/lwc/myComponent

[members]
# メタデータ種別:メンバー名
# CustomLabel:MyLabel
# Profile:Admin

ルール

  • [files] と [members] の 2 つのセクションで構成します。
  • 行頭の # はコメントです。
  • 空行は無視されます。
  • @isTest を持つ .cls ファイルを書くと、sf-release.sh が --test-level RunSpecifiedTests --tests <クラス名>（クラスごとに繰り返す）を、自動で設定します。
  • テストクラスを書くかどうかは、利用者の責任です。ローカルにあるテストクラスの書き忘れは、sf-check.sh が警告で知らせます。

remove-target.txt

# 削除対象のパスを列挙
force-app/main/default/classes/OldClass.cls
書いたあとは

構文は、git commit のときに自動で確認されます（pre-commit フック）。手動で確認するなら sf-check.sh です。確認の内容（パスの存在・書式・種類の可否・テストクラスの不足）は、そちらにあります。
