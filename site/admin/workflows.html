ワークフローの更新（sf-sync-wf）

sf-init が作るワークフローの一覧と、作成済みのプロジェクトのワークフローを、sf-tools の最新の雛形に合わせて更新する sf-sync-wf.sh の使い方です。

1. 自動で作られるワークフロー

sf-init.sh は、.github/workflows/ に、次の 5 つを作ります（雛形は sf-tools/templates/.github/workflows/）。

ファイル名前（name:）いつ動くか
wf-validate.yml[validate] デプロイ前検証すべてのブランチへの PR の作成・更新・再オープンのとき
wf-sequence.yml[sequence] マージ順序チェックmain / staging への PR の作成・更新のとき
wf-release.yml[release] デプロイmain / staging / develop への PR をマージしたあと
wf-propagate.yml[propagate] ブランチ伝播main への PR をマージしたあと
wf-metasync.yml[metasync] メタ同期平日の日本時間 9:00 / 12:00 / 15:00 / 18:00（3 時間おき）に自動で

順序外の PR を知らせる wf-sequence の仕組みは、sf-next.sh の説明にあります。

2. 雛形に合わせて更新する（sf-sync-wf.sh）

sf-sync-wf.sh            # 雛形との差分を表示し、確認のうえ、上書きする
sf-sync-wf.sh --check    # 差分があるかだけを調べる（何も変更しない）
sf-sync-wf.sh --remove wf-old.yml   # 雛形から廃止されたワークフローを削除する

sf-init.sh で作成済みの force-* に、あとから、ワークフローの修正（不具合の修正・安全対策など）を反映するコマンドです。sf-tools の雛形と、プロジェクトのワークフローを比べ、差分を表示して、確認のうえ、雛形の内容で上書きします。

管理者専用

CI/CD（リリース・検証）の動作が変わるため、実行の冒頭に、赤い警告ボックスと確認が表示されます（--check を除く）。sf-install.sh などから、自動では実行されません（利用者の意思なく、ワークフローが書き換わるのを防ぐためです）。

2.1 更新の手順（おすすめ）

  1. sf-job.sh で、ジョブ名 system-日付（例: system-20261006）の作業用ブランチを作ります。main から作られ、古くなりません。ワークフローの更新の PR だと、名前で分かります。

  2. そのフォルダで sf-sync-wf.sh を実行し、差分を確認して Y を答えます。

  3. git diff .github/workflows/ で、内容を確認します。

  4. sf-push.sh で、コミットしてプッシュします（ワークフローをプッシュするには、workflow スコープのある権限が必要です）。

  5. PR を出して、マージします。develop / staging がある構成では、通常の変更と同じ順序（develop → staging → main）で、PR を出します（次の PR 先は、sf-next.sh が案内します）。

2.2 動作

  • force-* フォルダの中で、環境ブランチ（branches.txt のブランチ。main / staging / develop など）以外でしか、実行できません。
  • sf-tools（~/sf-tools）が最新であることが必須です。実行の初めに、origin と比べ、遅れていれば、確認のうえ、sf-tools を更新し、更新した sf-tools で、自動的に、もう一度実行します（古い雛形で、プロジェクトのワークフローを書き換えないためです）。
    • origin に接続できない・更新を断った・sf-tools に未コミットの変更や未プッシュのコミットがある場合は、中断します。
    • --check は、何も変更しない（読み取り専用の）ため、sf-tools を更新せず、遅れていれば中断します。
  • 改行コード（CRLF / LF）だけの違いは、差分とみなしません。
  • 自動でコミット・プッシュはしません。
  • 雛形にないワークフローは、変更せず、表示するだけです。--remove で、雛形から廃止されたものだけを、二重に確認して削除できます（雛形にあるものは、削除できません）。
  • --check は、差分なしで終了コード 0、あれば 1 を返します。複数のリポジトリを見回るときに使えます。
