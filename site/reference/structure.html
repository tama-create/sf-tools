🗂️ ログとリポジトリ構成

ログが保存される場所と、2 種類のリポジトリ（利用者のプロジェクト force-* と、sf-tools 本体）の、フォルダの構成です。「このファイルは、どこにあるのだろう？」と思ったときに、見てください。

ログの確認

ログの場所は、コマンドによって、2 通りあります。

ログの場所コマンド
~/sf-tools/logs/<名前>.log（sf-tools 側。プロジェクトの外）sf-init.sh（sf-init.log。--add-tier・--reconnect も同じファイル）・sf-job.sh（sf-job.log）・sf-typecheck.sh（sf-typecheck.log）・sf-init.sh --verify（verify.log）・sf-init.sh --status（status.log）
実行した force-* フォルダの中の sf-tools/logs/<コマンド名>.log上以外の、すべてのコマンド

ログは、ほとんどのコマンドで、実行のたびに作り直されます（前回の内容は消えます）。sf-check.sh と sf-prepush.sh（git のフックから動くもの）だけは、実行のたびに追記されます。

force-* プロジェクトの構成

sf project generate が作る標準のファイルと、sf-init.sh が追加するものを、区別して示します（★ が、sf-tools が追加するものです）。

force-xxx/
├── .forceignore
├── .gitattributes                       ★ sf-tools 追加
├── .gitignore
├── .prettierrc / .prettierignore
├── .github/
│   └── workflows/                       ★ sf-tools 追加（CI/CD 5種）
│       ├── wf-release.yml               ★   デプロイ
│       ├── wf-validate.yml              ★   デプロイ前検証
│       ├── wf-sequence.yml              ★   マージ順序チェック
│       ├── wf-propagate.yml             ★   ブランチ伝播
│       └── wf-metasync.yml              ★   メタデータ自動同期
├── .vscode/                             ★ sf-tools 追加（推奨設定・拡張機能）
├── config/
│   └── project-scratch-def.json
├── .gitmessage                          ★ sf-tools 追加（コミットメッセージの雛形。sf-install.sh が、gitmessage から作る）
├── eslint.config.js
├── force-app/                           ← Salesforce メタデータ本体
├── jest.config.js
├── package.json
├── README.md                            ★ sf-tools 追加（プロジェクトの README の雛形）
├── scripts/
├── sfdx-project.json
└── sf-tools/                            ★ sf-tools 追加
    ├── config/
    │   ├── branches.txt                 ★   ブランチ↔組織エイリアスのマッピング
    │   └── metadata.txt                 ★   メタデータ同期対象の定義
    └── release/<branch>/
        ├── deploy-target.txt            ★   デプロイ対象メタデータ一覧
        └── remove-target.txt            ★   削除対象メタデータ一覧

│   ├── input.sh                ← 対話入力（read_input / read_key / press_enter / read_or_quit / read_secret / ask_yn）
│   ├── platform.sh             ← OS・外部コマンド（is_gitbash / run_isolated_home / check_sf_cli / open_browser）

│   ├── org.sh                  ← Salesforce 組織の接続情報の共通部品（ログイン先の選択・種類の判定・本番は main のみのガード）

│   ├── verify-common.sh        ← Hello World の本文・PR とワークフローの実行の部品（phases/init/verify.sh と e2e で共有）

│   └── typecheck.js            ← メタデータの種類ごとに、リリース・削除ができるかを確かめる（sf-typecheck.sh が呼ぶ。Node の標準機能のみ）

│       ├── reconnect.sh         ← --reconnect オプションで呼ばれる、接続先の組織の付け替え
│       ├── status.sh            ← --status オプションで呼ばれる、セットアップの診断（読み取りのみ）
│       ├── 01_check_env.sh
│       ├── 02_project_info.sh

│       ├── 06_pat_token.sh
│       ├── 07_slack.sh
│       ├── 08_initial_commit.sh
│       ├── 09_repo_rules.sh
│       └── 10_sf_auth.sh
├── hooks/
│   ├── pre-push                ← sf-hook.sh がプロジェクト側（.git/hooks/）へコピー
│   └── pre-commit              ← 同じく、sf-hook.sh がコピー

│   ├── jest.config.js
│   ├── README.md               ← プロジェクトの README の雛形
│   ├── package.json
│   ├── scripts/
│   ├── sfdx-project.json       ← __REPO_NAME__ プレースホルダーあり
│   └── sf-tools/
│       ├── config/             ← metadata.txt / branches.txt 雛形
│       └── release/__BRANCH__/ ← deploy-target.txt / remove-target.txt 雛形
├── config/                     ← sf-tools 自身の設定・データ（force-* には配布されない）
│   ├── metadata-capability.txt ← メタデータの種類ごとの、リリース・削除の可否の表（sf-typecheck.sh が確認。sf-check.sh が参照）

├── doc/                        ← 設計・手順・開発者向けの文書（Markdown）
├── tests/                      ← 単体テスト一式
│   └── e2e/                    ← 実環境での通し検証（sf-init の自動実行）
├── .github/workflows/          ← sf-tools 自身の CI（test.yml・e2e.yml）と、文書サイトの公開（pages.yml）
