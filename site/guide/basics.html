🌱 基本の使い方

フォルダの考え方を、先に押さえましょう。そのあと、新しい作業の始め方と、作業の再開のしかたを覚えます。覚えるコマンドは、2 つだけです。

始める前に: プロジェクトは、管理者が先に作ります

sf-tools は、管理者が、sf-tools の雛形で作った、決まった形のリポジトリ（force-XXXX）の上でしか動きません。管理者が先にリポジトリを作り、「できました」と連絡をくれてから、開発者は始めます。同時には進められません。XXXX の部分（プロジェクトの名前）は、管理者に聞いてください。まだ作られていないと、sf-job.sh は、何も見つけられずに止まります。

この章のあらすじ
  • 新しい作業を始めるときは、sf-job.sh を使います。
  • 前の続きを再開するときは、sf-start.sh を使います。
  • どちらも、最後に VS Code が開き、ターミナルにはランチャー（メニュー）が自動で開きます。始めたあとは、ランチャーの番号を押すだけで進められます（ランチャーの使い方）。

言葉とフォルダの構成

フォルダに、3 つの呼び名があります。言葉の意味は、用語集にもあります。

呼び方内容
プロジェクトforce-XXXX（リポジトリのクローン。VS Code で開く単位）。force- は固定で、XXXX は管理者が決める名前です（例: acme → force-acme）
作業単位プロジェクトのすぐ上のフォルダです（JOB-xxx や admin など）。同じ force-XXXX を、別々の作業として、同時に複数開くための入れ物です
作業フォルダ作業単位のフォルダを、まとめて置く場所です。どこでも構いません（sf-init.sh や sf-job.sh は、ここで実行します）
どのプロジェクトを使うかは、自動で決まります

フォルダの名前を、気にする必要はありません。sf-job.sh は、作業フォルダの中にある、クローンの情報から、プロジェクトを自動で見つけます。複数あるときは、番号で選びます。決まり方の詳しい説明は、sf-job.sh のリファレンスにあります。

困ったら、まず --help

すべての sf-*.sh コマンドは、--help（または -h）を付けると、概要・オプション・処理の流れを表示します。

sf-release.sh --help
sf-check.sh -h

新しい作業を始める（sf-job）

作業フォルダで、次のコマンドを実行します。

sf-job.sh                          # 作業フォルダの下のクローンから、プロジェクトが決まる（複数なら、番号で選ぶ）
sf-job.sh --project acme           # プロジェクトを指定する（force-acme）

ジョブ名（ブランチの名前になります）を入力するだけで、次のことが、自動で進みます。

  1. ジョブ名（例: JOB-20260323）で、GitHub 上に、main の最新から、作業用のブランチを作ります。

  2. 作業用のフォルダ（./ジョブ名/force-XXXX）に、そのブランチをコピーします（git clone）。

  3. sf-start.sh が、自動で動きます（Salesforce へのログイン・VS Code の起動。Git のフックの設定は、そのあと裏で行われます）。

うまくいかないとき
  • sf-job.sh は、管理者用のフォルダ（admin）や、force-* の中では動きません。作業フォルダで実行してください。
  • ほかのコマンドの困りごとは、トラブルシューティングを見てください。
Windows のパスの長さについて

クローンは、core.longpaths=true を付けて行います。Windows には、パスの長さが 260 文字までという上限があり、それを超えないようにするための設定です。組織に長い名前のメタデータ（例: DevOps Center の objectTranslations）があっても、クローンに失敗しません。この設定は、クローンの中に残るので、そのあとの git add・commit・push にも効きます。
