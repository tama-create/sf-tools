🧰 前提条件とインストール

sf-tools を使い始めるための、準備のページです。必要なツールをそろえて、sf-tools を置くまでを説明します。順番に進めれば大丈夫です。

Salesforce CLI は npm 版を使う

sf-tools は、Salesforce CLI（sf）の npm 版（npm install -g @salesforce/cli）で動かすことを前提にしています。npm 版も、Salesforce が案内しているインストール方法の 1 つです。

理由

Windows の Git Bash で、公式インストーラー版の Salesforce CLI を使うと、sf は成功しても、終了コード 1（失敗を表す値）を返し続けることがあります。同じバージョンの npm 版は、正しく返します。

sf-tools は、コマンドが成功したかどうかを、この終了コードで判断します。そのため、公式インストーラー版では、成功した処理も、失敗として扱われてしまいます。

確認する方法

次のコマンドを実行して、終了コード=0 と表示されれば、問題ありません。

command -v sf; sf --version; echo "終了コード=$?"

sf-tools も、起動するときに、同じ確認をします。0 でなかったときの動きは、次のとおりです。

コマンド終了コードが 0 でないとき
sf-init.sh案内を表示して、そこで止まります
毎日のコマンド（sf-start.sh・sf-release.sh・sf-metasync.sh・sf-update-secret.sh）案内を表示して、そこで止まります。途中で中途半端に止まるより、最初に止めるほうが安全だからです
sf-install.sh警告を表示するだけで、続けます。止めてしまうと、sf-tools 自身の更新が、止まってしまうためです

確認に成功すると、24 時間は、確認を省略します。

インストーラー版から npm 版へ入れ替える（Windows）

  1. npm 版を入れます。C:\Program Files\nodejs に書き込むので、管理者権限の Git Bash が必要な場合があります。

    npm install -g @salesforce/cli

  2. 公式インストーラー版を、アンインストールします（「設定 → アプリ」の「Salesforce CLI」、または C:\sf\Uninstall.exe）。

  3. 自動更新で増えた %LOCALAPPDATA%\sf\client を、削除します。

  4. 新しい Git Bash を開いて、上の確認コマンドを実行します。あわせて sf org list を実行して、これまでの組織が表示されることも、確かめてください。

この 2 つのフォルダは、削除しないでください

~/.sf と ~/.sfdx には、組織のログイン情報が入っています。入れ替えても、このログイン情報は残ります。VS Code を使っている場合は、入れ替えたあとに、VS Code を再起動してください。

更新するとき: sf-upgrade.sh が、npm 版を npm install -g @salesforce/cli@latest で更新します（手動でも、同じコマンドです）。

Mac・Linux: 同じく、npm 版をおすすめします。ほかの方法（pkg や Homebrew など）で入れた場合も、上の確認コマンドで終了コード 0 になれば、そのまま使えます。

sf-tools をインストールする

sf-tools を置く

git clone https://github.com/tama-create/sf-tools.git ~/sf-tools

PATH を設定する（おすすめ）

シェルの設定ファイルに、次の 1 行を追加すると、どこからでも、コマンド名だけで呼び出せます。

環境設定ファイル
Windows（Git Bash）・Linux~/.bashrc
Mac（標準のターミナル = zsh）~/.zshrc
 
# sf-tools
export PATH="$HOME/sf-tools/bin:$PATH"

追加したら、source ~/.bashrc（Mac は source ~/.zshrc）を実行して、反映します。ターミナルを開き直しても、同じです。
