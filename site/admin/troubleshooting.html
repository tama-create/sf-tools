トラブルシューティング（管理者向け）

セットアップや GitHub Actions が、うまく動かないときの、原因と直し方です。

1. sf-init.sh が途中でエラー終了した

ログを確認します。

cat ~/sf-tools/logs/sf-init.log

「どこで間違えたか分からない」ときは、管理者用の admin フォルダの中の force-* で、sf-init.sh --status を実行します。リポジトリ・ブランチ・ワークフロー・Secrets・Variables が、そろっているかを、✓（できている）・✗（不足。直し方も表示）で確認できます（何も変更しません。診断の説明）。

エラーの内容を確認して対処したら、同じフォルダで、sf-init.sh をもう一度実行します。途中まで進んでいた場合は、続きから再開する選択肢が出ます（途中で止まったとき）。

2. wf-metasync が「push declined due to repository rule violations」で失敗する

PAT_TOKEN が未設定か、権限が足りません。sf-init.sh は、登録のときに、スコープとリポジトリの管理者であることを確認しますが、登録したあとで、Token を無効にしたり、有効期限が切れたりすると、この状態になります。

新しい Token を発行して、リポジトリの Secrets の PAT_TOKEN を、登録し直してください。sf-update-secret.sh は JWT 用で、PAT_TOKEN は更新できません。

3. wf-validate / wf-sequence が動かない

ワークフローのファイルが、.github/workflows/ にあるかを確認します。ファイルがないときは、~/sf-tools/templates/.github/workflows/ から、wf-*.yml を、手動でコピーしてください（ワークフローの更新）。

4. CRLF の警告が出る

Windows での、改行コードの違いです。動作には影響しません。git checkout -- <ファイル> で、リセットできます。

5. pre-push フックが、プッシュをブロックする

main ブランチへの直接のプッシュは、禁止です。PR 経由でマージしてください。テストなどで、どうしても迂回が必要なときは、git push --no-verify を使います。

6. wf-metasync / wf-validate / wf-release が「自動化ツール（sf-tools）を取得」で失敗する

sf-tools は公開リポジトリのため、新しい wf-*.yml は、Token なしで clone します。このエラーは、以前のバージョンの雛形で作ったプロジェクトで、ワークフローが SF_TOOLS_TOKEN 付きで clone していて、その Token が、未設定・期限切れ・無効のときに起きます。

force-* 側の wf-metasync.yml / wf-validate.yml / wf-release.yml の clone の行を、新しい雛形と同じ、Token なしの形に直してください。

git clone -b ${{ vars.SF_TOOLS_BRANCH || 'main' }} https://github.com/tama-create/sf-tools.git ...

配布済みの force-* には、自動では反映されません。sf-sync-wf.sh で、雛形に合わせて更新できます。

7. 「差分抽出ツール（Salesforce Git Delta）をインストール」で TypeError が出て失敗する

エラーの例: TypeError: webidl.util.markAsUncloneable is not a function

ワークフローの Node.js が古いためです（@salesforce/cli の最新版は、Node 22 以上が必要です）。各 wf-*.yml の node-version を、22 以上にしてください。sf-tools/templates/ を直しても、配布済みの force-* には、自動では反映されないため、force-* 側の wf-*.yml も、直す必要があります（sf-sync-wf.sh）。
