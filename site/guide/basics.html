🌱 基本の使い方

フォルダの考え方を、先に押さえましょう。そのあと、新しい作業の始め方と、作業の再開のしかたを覚えます。覚えるコマンドは、2 つだけです。

始める前に: プロジェクトは、管理者が先に作ります

sf-tools は、管理者が、sf-tools の雛形で作った、決まった形のリポジトリ（force-XXXX）の上でしか動きません。管理者が先にリポジトリを作り、「できました」と連絡をくれてから、開発者は始めます。同時には進められません。XXXX の部分（プロジェクトの名前）と、リポジトリのオーナー（GitHub の組織名、またはアカウント名）は、管理者に聞いてください。まだ作られていないと、sf-job.sh は、GitHub にリポジトリが見つからずに止まります。リポジトリを読み書きする権限も必要です（足りないときは、GitHub が拒否して止まります。管理者に相談してください）。

この章のあらすじ
  • 新しい作業を始めるときは、sf-job.sh を使います。
  • 前の続きを再開するときは、sf-start.sh を使います。
  • どちらも、最後に VS Code が開き、ターミナルにはランチャー（メニュー）が自動で開きます。始めたあとは、ランチャーの番号を押すだけで進められます（ランチャーの使い方）。

言葉とフォルダの構成

フォルダに、3 つの呼び名があります。言葉の意味は、用語集にもあります。

呼び方内容
プロジェクトforce-XXXX（リポジトリのクローン。VS Code で開く単位）。force- は固定で、XXXX は管理者が決める名前です（例: acme → force-acme）
作業単位プロジェクトのすぐ上のフォルダです（JOB-xxx や admin など）。同じ force-XXXX を、別々の作業として、同時に複数開くための入れ物です
作業フォルダ作業単位のフォルダを、まとめて置く場所です。どこでも構いません（sf-init.sh や sf-job.sh は、ここで実行します）
どのプロジェクトを使うかは、自動で決まります

フォルダの名前を、気にする必要はありません。sf-job.sh は、作業フォルダの直下にあるクローン（JOB-xxx/force-XXXX など）が、どの GitHub のリポジトリからコピーしたものか（Git が記録している住所）を読み取って、プロジェクトを自動で見つけます。

  • 1 種類だけなら、自動で決まります。複数あるときは、番号で選びます。
  • 初めてで、まだクローンが 1 つもないときは、オーナー（GitHub のログインから、自分のアカウントと所属する組織を候補に出します）と、プロジェクトの名前（XXXX）を聞かれます。
  • --project・--owner で、はじめから指定することもできます。

決まり方の詳しい説明は、sf-job.sh のリファレンスにあります。

困ったら、まず --help

すべての sf-*.sh コマンドは、--help（または -h）を付けると、概要・オプション・処理の流れを表示します。

sf-release.sh --help
sf-check.sh -h

新しい作業を始める（sf-job）

作業フォルダで、次のコマンドを実行します。

sf-job.sh                          # 作業フォルダの下のクローンから、プロジェクトが決まる（複数なら、番号で選ぶ）
sf-job.sh --project acme           # プロジェクトを指定する（force-acme）
sf-job.sh --project acme --owner my-org   # オーナー（GitHub の組織名・アカウント名）も指定する

ジョブ名（ブランチの名前になります）を入力して、確認に答えるだけで、次のことが、自動で進みます。

  1. 使うプロジェクトを決め（上の「どのプロジェクトを使うかは、自動で決まります」）、GitHub にそのリポジトリがあるかを確かめます。

  2. ジョブ名（例: JOB-20260323）を入力します。最後に、ジョブ名・ブランチ・コピー先を表示して確認するので、よければ Y を押します（N / q で中断）。

  3. GitHub 上に、main の最新から、ジョブ名と同じ名前の作業用のブランチを作ります。

  4. 作業用のフォルダ（./ジョブ名/force-XXXX）に、そのブランチをコピーします（git clone。クローンともいいます）。

  5. そのフォルダで、sf-start.sh が、自動で動きます（Salesforce の組織へのログイン・VS Code の起動・ランチャーの起動。Git のフック（コミット・プッシュのときに自動で動くチェック）の設定などは、裏で行われます）。

ジョブ名の決まり
  • 英数字で始まり、英数字・-・_ だけの、1〜50 文字です。
  • main / staging / develop / admin は、使えません（共有の環境のブランチと、管理者用のフォルダの名前です）。
  • 同じ名前のフォルダ（./ジョブ名/force-XXXX）がすでにあるときも、入力し直しになります。
  • GitHub に、同じ名前のブランチがすでにあるときは、最後の変更をした人と日時を表示して、確認します。Y = そのブランチを使って続ける ／ N = 別の名前を入力し直す ／ q = 中断。ほかの人のブランチなら、N にしてください。
うまくいかないとき
  • sf-job.sh は、管理者用のフォルダ（admin）や、force-* の中では動きません。作業フォルダで実行してください。
  • ほかのコマンドの困りごとは、トラブルシューティングを見てください。

初めて実行したときに、聞かれること

初めての sf-job.sh では、次のことを、順番に聞かれます。画面の案内に沿って、答えてください。

聞かれることどうするか
GitHub へのログイン（まだのとき）sf-job.sh が、gh auth login を始めます。画面の案内に沿って、ブラウザでログインします
オーナーとプロジェクト（自動で決まらないとき）オーナーは、候補が複数あれば番号で選びます。プロジェクトの名前（XXXX）は、入力して Y / N で確かめます（上の説明）
ジョブ名と、最後の確認この作業の名前です（例: JOB-20261024）。ブランチの名前になります（ジョブ名の決まり）。最後に、内容を確かめて Y を押します
組織のエイリアスエイリアスは、接続する組織に付ける、短い呼び名です（例: myorg）。ここでは、自分用の組織（個人の Sandbox・Developer Edition など）に付けます。prod / staging / develop / main は、共有の環境の名前（予約名）なので、付けないでください（その名前の組織には、手元から、検証もリリースもできません。ランチャーの 4 Dryrun・5 Deploy が止まります）。同じエイリアスで、前にログインしていた組織の接続は、いったん消えて、新しいログインに置き換わります
ログイン先1 = 本番・Developer Edition（login.salesforce.com）／ 2 = Sandbox（test.salesforce.com。Enter だけで、これになります）／ 3 = 組織の URL を入力（https で、salesforce.com か force.com の URL）。q で中断
Salesforce へのログインブラウザが開きます。自分用の組織に、ログインしてください。ログインに失敗すると、そこで止まります（VS Code もランチャーも開きません）。もう一度実行してください

組織へのログインは、sf-job.sh を実行するたびに聞かれます（毎回、新しいコピーを作るため、接続の設定もまだないからです）。sf-start.sh で同じフォルダの作業を再開するときは、すでに接続していれば、聞かれません。

止めたいときは、Ctrl+C ではなく q
  • sf-job.sh・sf-start.sh・ランチャーでは、Ctrl+C が効きません。止めたいときは、入力を求められたところで q を押します。
  • ただし、Salesforce CLI（sf）や npm の実行中に Ctrl+C を押すと、そのコマンドだけが止まることがあります。
  • 途中で止まっても、それまでに作ったブランチ・フォルダは、消えません。ブランチを作ったあとにコピー（クローン）が失敗したときは、同じジョブ名でもう一度実行し、「そのブランチを使って続ける」で Y を押すと、続きから進められます。
  • sf-job.sh は、ランチャーを q で終了するまで、終わりません。
Windows のパスの長さについて

クローンは、core.longpaths=true を付けて行います。Windows には、パスの長さが 260 文字までという上限があり、Git がそれを超える長いパスも扱えるようにするための設定です。組織に長い名前のメタデータ（例: DevOps Center の objectTranslations）があっても、クローンに失敗しません。この設定は、クローンの中に残るので、そのあとの git add・commit・push にも効きます。

作業を再開する（sf-start）

前日の続きなど、すでにあるブランチで再開するときは、force-* フォルダの中で実行します。

cd 作業フォルダ/JOB-20261024/force-acme
sf-start.sh

次のことを、順に行います。

  1. Salesforce CLI（sf）が使えるかを確かめます（インストールの npm 版が前提です）。
  2. 組織に接続済みかを確かめます。接続済みなら、ログインを省きます。まだなら、初めてのときと同じく、エイリアス・ログイン先を聞いて、ブラウザでログインします。
  3. VS Code を開きます。
  4. 裏で、準備を進めます（~/sf-tools の更新・Git のフックの設置・リリース用のフォルダの準備・開発ツールの更新など）。
  5. 最後に、ランチャーを開きます。
sf-jobsf-start
実行する場所作業フォルダ（作業単位を置く場所）force-* フォルダの中
ブランチの作成自動で作る作らない（すでにあるブランチを使う）
組織へのログイン毎回（新しいコピーのため）まだ接続していないときだけ

使うタイミング新しい作業を始めるとき2 回目以降に、作業を再開するとき

別の組織に切り替えるときは、sf-restart.sh（ランチャーの 7 Restart）を使います。接続済みでも、エイリアスの入力とログインから、やり直します。ログインに失敗したときは、元の接続の設定に戻ります。
