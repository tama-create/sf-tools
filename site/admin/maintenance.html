🔧 構成の変更と診断

セットアップが済んだあとの、管理者のメンテナンスです。段階（ブランチの階層）を足す、接続先の組織を付け替える、いまの状態を診断する、の 3 つを説明します。どれも、force-* フォルダの中（管理者用の admin/force-XXXX）で実行します。

まず困ったら、診断から

「どこで間違えたか分からない」というときは、sf-init.sh --status から始めてください。何も変更せずに、足りないものと、直し方を教えてくれます。

Salesforce 組織の接続の考え方

段階（main / staging / develop）と、組織の種類は、結びつけていません。どの段階にも、本番・Sandbox・Developer Edition などを、自由につなげられます（main に Sandbox や Developer Edition をつないでも構いません）。

本番の組織は、main にだけつなげます

staging や develop に、本番の組織をつなごうとすると、ログインのあとで組織の種類を確かめて、そこで止まります。本番を、うっかり、開発用の段階につなげないための仕組みです。

ログイン先の選び方

段階ごとに、ログイン先を、次の 3 つから選びます（Enter だけなら 2 番です）。組織の種類ではなく、URL で選びます。

  1. https://login.salesforce.com — 本番・Developer Edition・Trial など
  2. https://test.salesforce.com — Sandbox（安全なおすすめ。本番に影響しません）
  3. 組織の URL を入力（My Domain。例: https://会社名.my.salesforce.com）

ログインすると、組織の ID・名前・種類（本番 / Sandbox / Developer Edition / Trial）を、組織から読み取って表示します。読み取った内容は、保存されます。

段階を足す（--add-tier）

セットアップのあとで、main だけの構成から、staging・develop へ、段階を足せます。

# force-* フォルダの中で実行
sf-init.sh --add-tier staging    # main のみ → main + staging
sf-init.sh --add-tier develop    # main + staging → main + staging + develop
[最初]    main のみ
    ↓  sf-init.sh --add-tier staging
[2 段階]  main + staging
    ↓  sf-init.sh --add-tier develop
[3 段階]  main + staging + develop

足すときに、次のことが、自動で行われます。

  • branches.txt の更新
  • GitHub に、新しいブランチを作る
  • 足した段階の、認証情報（Secret / Variable）の登録
  • branches.txt のコミットとプッシュ（develop を足すときは、main に直接プッシュせず、PR を作ります）
  • staging を飛ばして、main から develop を足すことは、できません（エラーになります）。
  • 最初のセットアップとは、順序が逆です。段階を足すときは、先に Salesforce に接続して、成功してから、ブランチと PR を作ります。接続に失敗したときに、GitHub 側を、変更しないためです。
  • 終わると、実行する前のブランチ（admin）に戻ります。

段階を減らすとき（手動）

段階を減らす操作は、自動化していません
  • ブランチの削除・Ruleset の変更・Secrets / Variables の削除など、影響が広い操作だからです。
  • まちがえて削除すると、元に戻せないおそれがあります。
  • 必要になる機会が少なく、1 回で済む手作業と判断しました。

次の順番で、手作業で行います。

  1. GitHub の Repository Ruleset を更新します（減らす段階のブランチを、対象から外します）。Ruleset の設定によっては、先に外さないと、ブランチを削除できません。

  2. branches.txt から、減らす段階を削除して、コミットしてプッシュします。

  3. GitHub で、ブランチ（staging / develop）を削除します。

  4. GitHub の Secrets / Variables から、その段階の SF_CONSUMER_KEY_* / SF_USERNAME_* / SF_INSTANCE_URL_* を削除します。

接続先を付け替える（--reconnect）

sf-init.sh --reconnect <段階>      # 段階: main / staging / develop

1 つの段階について、接続先の Salesforce 組織を、別の組織に付け替えます。ログイン先の選び方と、本番は main にだけつなげるというルールは、最初の章のとおりです。

セットアップを診断する（--status）

sf-init.sh --status

🔍 読み取りのみ 何も変更せずに、いまの状態を調べます。「どこで間違えたか分からない」ときの、最初の手がかりです。

  • リポジトリ・ブランチ・ワークフロー・Secrets・Variables が、そろっているかを調べます。足りないものは、直し方もいっしょに表示します。
  • 段階ごとの接続先（ログイン先・組織の種類・ユーザー・組織の ID・最後に確かめた日時）の一覧も、表示します。
  • 項目ごとに、次の記号で示します。
    • ✓ できている
    • ✗ 足りない（直し方を表示）
    • ！ 注意
    • ？ 確認できなかった
    足りないものがあると、終了コードは 1 になります。
  • Salesforce 側（外部クライアントアプリ・JWT 接続）は、ログインが必要なので、調べません。直近の wf-metasync や wf-release が成功していれば、接続はできています。
