コマンド一覧

sf-tools のコマンドは、すべて ~/sf-tools/bin/ にあります。どれも --help / -h で、概要・オプション・処理の流れを表示できます。

1. 一覧

「ランチャー」は、sfl のメニューから選べるコマンドです（ランチャー）。⚠️ は管理者専用です（次の節）。

コマンド用途種別

sf-start.sh開発環境を起動する（作業の再開）ランチャー
sf-launcher.sh（sfl）ランチャー本体（メニューから選んで実行）ランチャー外
sf-check.shターゲットファイルの構文を確認するランチャー
sf-dryrun.shdry-run で検証するランチャー
sf-release.sh検証（既定は dry-run）・リリース—
sf-deploy.sh⚠️ 接続中の組織への強制リリース（確認あり。個人用の組織だけ）ランチャー
sf-push.shカレント配下をコミットしてプッシュするランチャー
sf-next.sh次の PR 先を確認するランチャー

詳しい説明は、管理者ガイドに載せる予定です（準備中）。それまでは、README を見てください。

コマンド用途
sf-init.sh新規プロジェクトの初期セットアップ。段階の追加（--add-tier）・診断（--status）・接続先の付け替え（--reconnect）も
sf-init.sh --verify⚠️ 実際のリポジトリ・組織で、リリースと削除が動くことを確認する（Hello World）

2. 管理者専用コマンドの安全ガード

⚠️ のついたコマンドは管理者専用です。実行すると、赤い警告ボックスが表示され、続行の確認（Y / N / q）を求められます。一般の開発者が誤って実行したときは、N または q で中断できます。

  • GITHUB_ACTIONS=true が設定されている環境（GitHub Actions 上）では、確認をスキップして自動で実行します。
  • gh コマンドを使うコマンドは、起動時に、gh の認証ユーザーとリポジトリのオーナーが一致するかを確認します。不一致なら中断します。
    ただし、オーナーが GitHub 組織（例: tamashimon-org）で、認証ユーザーがその組織の有効な管理者（admin）なら、そのまま続行します。組織の一般メンバーや、組織の情報を取得できない場合は中断します（gh auth switch で正しいアカウントに切り替えてから、もう一度実行してください）。
