📖 用語集

この文書に出てくる言葉を、やさしく説明します。「これは何だろう？」と思ったら、ここを見てください。すべてを覚える必要はありません。

この文書での言葉の使い方
  • 管理者は、「プロジェクト管理者」のことです（次の節）。Salesforce のシステム管理者と同じ人のこともありますが、役割は別です。
  • リリースとデプロイは、同じ意味です（変更を Salesforce の組織に反映すること）。コマンドの名前に合わせて、どちらも出てきます。

人と役割

言葉意味
プロジェクト管理者（管理者）新しいプロジェクトを作り、接続や設定を整える担当の方です。最初に 1 回の準備をして、そのあとは、ときどき見直します。Salesforce のシステム管理者と同じ人のこともありますが、GitHub の設定など、別の作業も受け持ちます
開発者Apex や LWC、項目、画面などを作って、変更を出す方です。日々の作業で、sf-tools のコマンドをいちばん使います
レビュアーPR（変更を取り込む依頼）の内容を見て、取り込んでよいかを決める方です

プロジェクトとフォルダ

言葉意味
プロジェクト（force-XXXX）1 つの Salesforce 開発の単位です。GitHub 上のリポジトリ 1 つに対応します。名前は force- で始まり、XXXX の部分は管理者が決めます（例: force-acme）
リポジトリファイルと、その変更の履歴を、しまっておく場所です（GitHub 上にあります）
クローン（clone）リポジトリを、自分のパソコンにコピーすることです。コピーしたものも、クローンと呼びます
作業フォルダ作業用のフォルダを、まとめて置く場所です。どこでも構いません（おすすめは ~/sf のような短い名前）
作業単位1 つの作業のためのフォルダです（JOB-日付 など）。同じプロジェクトを、別々の作業として、同時に開くための入れ物です

Git と GitHub

言葉意味
ブランチ変更を、本線から分けて進めるための「枝」です。作業ごとに 1 本作ります。本線を汚さずに、安心して試せます
コミット変更を、履歴に 1 つ記録することです
プッシュ（push）手元の変更を、GitHub に送ることです
PR（プルリクエスト）「この変更を取り込んでください」という依頼です。取り込む前に、自動の検証と、レビュアーの確認が入ります
マージPR の変更を、取り込み先のブランチに合わせることです
ワークフロー（GitHub Actions）GitHub の上で、自動で動く処理です。この文書では、検証・リリース・同期などを行う仕組みを、ワークフローと呼びます。人が操作しなくても、PR を作ると動き出します
フックコミットやプッシュの直前に、自動で動くチェックです。まちがった内容を、送る前に止めてくれます
ブランチ保護（Ruleset）main などの大切なブランチに、直接、変更を送れないようにする GitHub の設定です。必ず PR を通すので、検証を飛ばせません

段階（環境）と組織

言葉意味
組織（org）Salesforce の環境 1 つのことです。本番・Sandbox・Developer Edition などがあります
段階変更を、順番に確かめながら本番へ進めるための、段のことです。develop（開発）→ staging（検証）→ main（本番）の 3 段が標準です。段ごとに、ブランチと Salesforce の組織が、1 つずつ対応します。小さなプロジェクトは、main だけの 1 段でも使えます
環境段階と同じ意味で使います（本番環境・検証環境・開発環境）

リリースの言葉

言葉意味
リリース（デプロイ）変更を、Salesforce の組織に反映することです
dry-run（検証）実際には反映せずに、「反映できるか」だけを確かめることです。本番を変えずに、安心して試せます。sf-tools のリリースは、まず dry-run が基本です
メタデータApex クラス・項目・画面レイアウトなど、Salesforce の設定や部品のことです
ターゲットファイル「何を反映するか」「何を削除するか」を書いておくファイルです（deploy-target.txt と remove-target.txt）
メタデータの同期組織の最新の状態を、Git に取り込む処理です。手元の変更とは関係なく、組織で直接加えられた変更も、Git に残せます

認証と秘密の情報

言葉意味
SecretGitHub に登録して、人にも見えないように隠しておく情報です（秘密鍵や Token など）
VariableGitHub に登録する情報のうち、見えても問題のないものです（ユーザー名や URL など）
Token（トークン）長い英数字の文字列で、「合言葉」のように使います。パスワードの代わりに、ツールどうしが、おたがいを確かめます
PATGitHub の Personal Access Token のことで、GitHub の「合鍵」のようなものです。ワークフローが、リポジトリを更新するために使います
JWT 認証パスワードの入力なしで、秘密鍵を使って、Salesforce にログインする方法です。GitHub 上のワークフローが、自動でログインするために使います
外部クライアントアプリSalesforce の側に作る、「このツールからのログインを許可する」という登録です。セットアップのときに、自動で作られます
