自動実行コマンド

ほかのコマンドや、git のフック、GitHub Actions から自動で呼ばれるコマンドです。人が直接実行することは、ほとんどありません。全体の一覧は コマンド一覧 にあります。

sf-install.sh

sf-install.sh

sf-tools 自体の更新と、プロジェクト側の初期ファイルの整備を行います。通常は、sf-start.sh から自動で実行されます。

主な処理（この順序）

  1. ~/sf-tools を最新にする
  2. 設定ファイルの雛形を作る
  3. pre-push フックをインストールする
  4. release/<ブランチ名>/ を準備する
  5. npm install（package.json があるとき）
  6. 必要に応じて、sf-upgrade.sh をバックグラウンドで実行する（24 時間おき）

sf-upgrade.sh

sf-upgrade.sh

npm・Salesforce CLI・Git を更新します。sf-install.sh から、24 時間おきに自動で実行されます。

sf-prepush.sh

git push の前に自動で実行される、チェックのスクリプトです（pre-push フックの本体）。

主な処理

  • main への直接のプッシュを禁止する
  • 自分のブランチの、リモートとの差分を、先に同期する
  • main の未取り込みの更新を確認し、必要なら自動で rebase する
  • sf-check.sh で、ターゲットファイルの構文を検証する
  • branches.txt に、origin にまだないブランチ名があっても、プッシュは止めない（その名前だけ取得せず、警告する）

sf-precommit.sh

git commit のときに自動で実行される、pre-commit フックの本体です。直接実行することはありません。

主な処理

  • sf-check.sh で、ターゲットファイルの構文を確認する
  • エラーがあれば、コミットを中止する

sf-metasync.sh

sf-metasync.sh

組織の最新のメタデータを取得して、Git に反映します。主に、GitHub Actions からの定期実行を想定しています。

管理者専用

実行の前に、赤い警告ボックスと確認が表示されます。GITHUB_ACTIONS=true のときは、確認をスキップして自動で実行します。

役割

  • 組織の最新のメタデータを取得する
  • Git へ反映する
  • 変更があるときだけ、コミットしてプッシュする
  • 変更がなくても、前回の同期のコミットのプッシュが失敗して、未プッシュのコミットが残っているときは、確認のうえ、プッシュだけ行う
  • main へのプッシュは、pre-push フックを通さない（--no-verify。このコマンド専用です。GitHub の保護の設定は、そのまま効きます）

取得するメタデータの種類（sf-tools/config/metadata.txt）

取得する種類は、各プロジェクトの sf-tools/config/metadata.txt で決まります（sf-init が、雛形から作ります）。設定ファイルだけで調整でき、コードの変更は要りません。

前提

雛形の標準セットは、Developer Edition（Sales・Service の標準機能つき）でのみ、リリースと削除を確認しています。ほかのエディション・製品（Service Cloud・Experience Cloud・業種クラウドなど）で使う場合は、必要な種類を足してください。

区分既定内容
1. 標準セット有効Developer Edition で、リリース・削除を確認済み（Apex・LWC・オブジェクト・項目・Layout・権限・レポート・ワークフローなど）
2. 標準だが制限あり有効更新のみ・権限による・一部未確認（StandardValueSet・Flow・Settings など。理由は、ファイル内のコメント）
3. 機能が必要なものコメントアウトService Cloud 系（Entitlement・Omni-Channel・Knowledge）・Experience Cloud 系。使う組織だけ、コメントを外す
4. 未確認コメントアウト確認できていない種類。使う場合は、外して、リリースを確かめる
5. 参考コメントアウトそのほかの種類の候補（業種クラウド・AI・分析など）
  • 取得の対象に、その組織にない種類があっても、警告になるだけで、取得は続きます。
  • 種類ごとの確認の状況は、sf-typecheck.sh --coverage で見られます（変更セットで扱える種類のうち、確認済み・未確認の数）。
  • リリース・削除できないと確認済みの種類は、ターゲットファイルに書くと、sf-check.sh が止めます（警告だけの種類もあります）。
  • すでに作成済みのプロジェクトの metadata.txt は、雛形が更新されても、変わりません。
