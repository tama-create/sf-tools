前提条件とインストール

sf-tools を使い始めるために、必要なツールを用意して、sf-tools を置くまでの手順です。

1. 動作環境

実際に動かして確かめた環境だけを書いています。

環境使う場面確認した内容
Windows（Git Bash）手元のパソコン（開発者・管理者）自動テストに合格。さらに、実際の GitHub と Salesforce を使って、初期セットアップから、Salesforce へのリリース・削除まで、最初から最後まで動かして確認しました
Mac（macOS）手元のパソコン同じ確認を、Mac mini の実機で行いました
WSL（Windows の中の Ubuntu）手元のパソコン同じ確認を行いました
Linux（GitHub Actions のサーバー）自動で動く部分（人は触りません）: 変更の検証・Salesforce へのリリース・メタデータの同期実際の Salesforce に対して、検証・リリース・同期が成功することを確認しました
  • 確認に使った Salesforce は、Developer Edition（開発者向けの無料の組織）です。ほかのエディション（Enterprise など）や Sandbox では、確認していません。
  • 自動テストとは、プログラムの各部分が正しく動くかを、機械が確かめるものです。GitHub 上で、変更のたびに自動で実行され、Linux・Mac・Windows の 3 つの環境で、合格しています。
  • Linux を、手元のパソコンとして使うことは、想定していません（Linux は、自動で動くサーバーとしてだけ使います）。
  • Mac は、標準のターミナル（zsh）と標準の Bash のままで動きます。Homebrew などで、Bash を入れ直す必要はありません。

3. Salesforce CLI は npm 版を使う

sf-tools は、Salesforce CLI（sf）の npm 版（npm install -g @salesforce/cli）を前提としています。npm 版も、Salesforce が案内しているインストール方法の一つです。

3.1 理由

Windows の Git Bash で、Salesforce CLI の公式インストーラー版（winget 版を含む可能性があります）を使い、自動更新が入った状態になると、sf が成功しても、終了コード 1 を返し続けることがあります（同じバージョンの npm 版は、正しく返します。Salesforce の起動用ファイルの問題と考えられます）。

sf-tools は、コマンドの成否を終了コードで判定するため、この環境では、成功した処理も失敗扱いになります。

3.2 確認方法

次のコマンドで、終了コード=0 と表示されれば問題ありません。

command -v sf; sf --version; echo "終了コード=$?"

sf-tools も、起動時に同じ確認をします。

コマンド終了コードが 0 でないとき
sf-init.sh案内を表示して中断
日常のコマンド（sf-start.sh・sf-release.sh・sf-metasync.sh・sf-update-secret.sh）案内を表示して中断。途中で中途半端に止まるより、最初に止めるほうが安全だからです
sf-install.sh警告を表示するだけで続行。中断すると、sf-tools 自身の最新化が止まってしまうためです

確認に成功した場合は、24 時間は、確認を省略します。

3.3 インストーラー版から npm 版への入れ替え（Windows）

  1. npm 版を入れます。C:\Program Files\nodejs に書き込むため、管理者権限の Git Bash が必要な場合があります。

    npm install -g @salesforce/cli

  2. 公式インストーラー版をアンインストールします（「設定 → アプリ」の「Salesforce CLI」、または C:\sf\Uninstall.exe）。

  3. 自動更新で増えた %LOCALAPPDATA%\sf\client を削除します。

  4. 新しい Git Bash を開いて、上の確認コマンドを実行します。あわせて sf org list で、既存の組織が表示されることを確認してください。

削除してはいけないフォルダ

~/.sf と ~/.sfdx は、組織のログイン情報が入っているため、削除しないでください。入れ替えても、ログイン情報は残ります。VS Code を使っている場合は、入れ替え後に VS Code を再起動してください。

更新: sf-upgrade.sh が、npm 版は npm install -g @salesforce/cli@latest で更新します（手動で行う場合も同じコマンドです）。

Mac・Linux: 同じく npm 版をおすすめします。ほかの方法（pkg・Homebrew など）で入れた場合も、上の確認コマンドで終了コード 0 になれば、そのまま使えます。

4. sf-tools をインストールする

4.1 sf-tools を置く

git clone https://github.com/tama-create/sf-tools.git ~/sf-tools

4.2 PATH を設定する（おすすめ）

シェルの設定ファイルに次の 1 行を追加すると、どこからでもスクリプト名だけで呼び出せます。

環境設定ファイル
Windows（Git Bash）・Linux~/.bashrc
Mac（標準のターミナル = zsh）~/.zshrc
 
# sf-tools
export PATH="$HOME/sf-tools/bin:$PATH"

追加したあとで、source ~/.bashrc（Mac は source ~/.zshrc）を実行して反映します。
