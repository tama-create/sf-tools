構成の変更と診断

セットアップが済んだあとの、管理者のメンテナンスです。段階（ブランチの階層）の追加、接続先の組織の付け替え、いまの状態の診断を扱います。どれも force-* フォルダの中（管理者用の admin/force-XXXX）で実行します。

Salesforce 組織の接続の考え方

段階（main / staging / develop）と組織の種類は、結びつけません。どの段階にも、本番・Sandbox・Developer Edition などを、自由につなげます（main に Sandbox や Developer Edition でも構いません）。

本番の組織は、main にしかつなげません

staging や develop に、本番をつなごうとすると、ログインのあとに、組織の種類を読み取って、中断します。

ログイン先の選び方

段階ごとに、ログイン先を、次の 3 つから選びます（Enter は 2）。種類ではなく、URL で選びます。

  1. https://login.salesforce.com — 本番・Developer Edition・Trial など
  2. https://test.salesforce.com — Sandbox（安全なおすすめ。本番に影響しません）
  3. 組織の URL を入力（My Domain。例: https://会社名.my.salesforce.com）

ログインのあとに、組織の ID・名前・種類（本番 / Sandbox / Developer Edition / Trial）を、組織から読み取って、表示し、保存します。

段階を足す（--add-tier）

セットアップのあとで、main だけの構成を、staging・develop へ広げられます。

# force-* フォルダの中で実行
sf-init.sh --add-tier staging    # main のみ → main + staging
sf-init.sh --add-tier develop    # main + staging → main + staging + develop
[初期]    main のみ
    ↓  sf-init.sh --add-tier staging
[2段階]   main + staging
    ↓  sf-init.sh --add-tier develop
[3段階]   main + staging + develop

追加のときに、自動で行われる内容は、次のとおりです。

  • branches.txt の更新
  • リモートのブランチの作成（GitHub）
  • 追加した段階の、JWT 認証情報（Secret / Variable）の登録
  • branches.txt のコミットとプッシュ（develop を追加するときは、main へは直接プッシュせず、PR を作ります）
  • main → develop のように、staging を飛ばした追加は、エラーになります。
  • 初回のセットアップとは、処理の順序が逆です。段階の追加では、先に Salesforce に接続し、成功してから、ブランチと PR を作ります（接続に失敗したときに、GitHub 側を、変更しないためです）。
  • 終わると、実行前のブランチ（admin）に戻ります。

段階を減らすとき（手動）

段階の削除（スケールダウン）は、自動化していません
  • ブランチの削除・Ruleset の変更・Secrets / Variables の削除など、影響の範囲が広いためです。
  • 誤って削除すると、元に戻せないおそれがあります。
  • 需要が少なく、1 回で済む手動の操作と判断しました。

手動で必要な作業は、次のとおりです。

  1. GitHub でブランチを削除する（staging / develop）。

  2. branches.txt から、該当の段階を削除して、コミットしてプッシュする。

  3. GitHub の Secrets / Variables から、SF_CONSUMER_KEY_* / SF_USERNAME_* / SF_INSTANCE_URL_* を削除する。

  4. GitHub の Repository Ruleset を更新する（削除した段階のブランチを、対象から外す）。

接続先の付け替え（--reconnect）

sf-init.sh --reconnect <段階>      # 段階: main / staging / develop

1 つの段階の、接続先の Salesforce 組織を、付け替えます。ログイン先の選び方と、本番は main だけというルールは、1 章のとおりです。

セットアップの診断（--status）

sf-init.sh --status

「どこで間違えたか分からない」ときの、最初の手がかりです。読み取りのみで、何も変更しません。

  • リポジトリ・ブランチ・ワークフロー・Secrets・Variables が、そろっているかを診断します。不足は、直し方つきで表示します。
  • 段階ごとの接続先（ログイン先・組織の種類・ユーザー・組織の ID・最終確認の日時）の一覧も表示します。
  • 項目ごとに、✓（できている）・✗（不足。直し方を表示）・！（注意）・？（確認できず）で示します。不足があれば、終了コード 1 です。
  • Salesforce 側（外部クライアントアプリ・JWT 接続）は、ログインが必要なため、確認しません。直近の wf-metasync / wf-release が成功していれば、接続はできています。
