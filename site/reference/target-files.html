📝 ターゲットファイルの書き方

「何を反映するか」と「何を削除するか」を、2 つのファイルに書いておきます。ファイルは、force-XXXX フォルダの中の sf-tools/release/<ブランチ名>/ に置きます（パソコンに置いた ~/sf-tools とは、別のフォルダです）。ブランチ名は、sf-job.sh で作った作業の名前です。

このページの要点
  • 書くのは、deploy-target.txt（反映するもの）と remove-target.txt（削除するもの）の 2 つです。
  • 書き終わったら、ランチャーの [1] Check（sf-check.sh）で、書き方を確かめられます。git commit と git push のときにも、自動で確かめます。
ファイル役割
deploy-target.txtデプロイするメタデータを列挙する
remove-target.txt削除するメタデータを列挙する

ファイルの置き場所

  • フォルダ sf-tools/release/<ブランチ名>/ と、2 つのファイルの雛形は、sf-start.sh がバックグラウンドで実行する sf-install.sh が、作業用のブランチで用意します（main ブランチでは作りません）。
  • どのフォルダを使うかは、今の Git のブランチではなく、sf-tools/release/branch_name.txt（sf-install.sh が書き込む、Git の管理外の手元のファイル）に書かれたブランチ名で決まります。sf-check.sh・sf-release.sh の両方が、このファイルを読みます。
  • sf-release.sh は、branch_name.txt と 2 つのファイルの、どれか 1 つでもないと中断します。sf-check.sh は、ないファイルの検証を飛ばします（branch_name.txt がないときは、警告を出して、何も検証せずに成功します）。

deploy-target.txt

[files]
# ファイルパスで指定
force-app/main/default/classes/MyController.cls
force-app/main/default/classes/MyControllerTest.cls
force-app/main/default/lwc/myComponent

[members]
# メタデータ種別:メンバー名
# CustomLabel:MyLabel
# Profile:Admin

ルール

  • [files] と [members] の 2 つのセクションで構成します。
  • 行頭の # はコメントです。
  • 空行は無視されます。
  • [files] には、ファイルまたはフォルダのパスを書きます（リポジトリのルートからの相対パス。存在しないパスは、エラーです）。フォルダは、1 つのコンポーネント・オブジェクトを丸ごと指すものだけ書けます（lwc/コンポーネント名・aura/コンポーネント名・objects/オブジェクト名）。classes や . のような広いフォルダは、対象が広がりすぎる（remove-target.txt では、組織のメタデータが広範囲に削除される）ため、エラーです。絶対パスや、要素に .. を含むパス（リポジトリの外を指すパス）も、存在していてもエラーです。
  • [members] には、種別名:メンバー名 の形で書きます（: がない・先頭か末尾が : の行は、エラーです）。
  • 最初の [files] / [members] の行より前に書いた行は、[files] として扱われます。
  • リリース・削除できないと確認済みの種類（config/metadata-capability.txt で ng）を書くと、sf-check.sh がエラーにします。条件によってできないことがある種類（limited）は、警告です。deploy-target.txt はリリースの可否、remove-target.txt は削除の可否で判定します。
  • [files] に、@isTest（大文字・小文字を区別しない）を持つ .cls ファイルを書くと、sf-release.sh が --test-level RunSpecifiedTests --tests <クラス名>（クラスごとに繰り返す）を、自動で設定します。
  • deploy-target.txt と remove-target.txt の両方に、対象が 1 件もない（コメントと空行だけ）ときは、sf-release.sh は「デプロイ対象なし。正常終了します。」と表示して、何もせず、正常に終わります。
  • テストクラスを書くかどうかは、利用者の責任です。ローカルにあるテストクラスの書き忘れは、sf-check.sh が警告で知らせます（先頭の ./ は、付けても付けなくても、同じに扱います）。

remove-target.txt

# 削除対象のパスを列挙
force-app/main/default/classes/OldClass.cls

書き方は、deploy-target.txt と同じです（[files] と [members]）。

  • 削除は、deploy-target.txt のデプロイより先に行われます（--pre-destructive-changes）。
  • deploy-target.txt が空で、remove-target.txt にだけ対象があるときは、削除だけを行います。
  • 組織にない削除対象を、エラーにしたくない（後始末など）ときは、# @ignore-missing で始まるコメント行（行頭・# の後の空白は可）を書きます。--ignore-warnings が付き、削除以外の警告も、エラーになりません。通常のリリース・削除では、書かないでください（綴りの誤りを見落とすため）。
書いたあとは

書き方は、git commit と git push のときに自動で確認されます（pre-commit フック・pre-push フック）。手動で確認するなら sf-check.sh です。確認の内容（パスの存在・書式・種類の可否・テストクラスの不足）は、そちらにあります。
