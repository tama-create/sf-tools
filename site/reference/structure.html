🗂️ ログとリポジトリ構成

ログが保存される場所と、作業フォルダ・2 種類のリポジトリ（利用者のプロジェクト force-* と、sf-tools 本体）の、フォルダの構成です。「このファイルは、どこにあるのだろう？」と思ったときに、見てください。

ログの確認

ログの場所は、コマンドによって、2 通りあります。

ログの場所コマンド
~/sf-tools/logs/<名前>.log（sf-tools 側。プロジェクトの外）sf-init.sh（sf-init.log。各 Phase も追記する。--add-tier・--reconnect・--status も同じファイル）・sf-init.sh --verify とセットアップの最後の動作の確認（verify.log）・sf-job.sh（sf-job.log）・sf-typecheck.sh（sf-typecheck.log）
実行した force-* フォルダの中の sf-tools/logs/<コマンド名>.log上以外の、すべてのコマンド（ランチャー sf-launcher.sh は、ログを作りません）

ログは、ほとんどのコマンドで、実行のたびに作り直されます（前回の内容は消えます）。sf-init.sh（--add-tier・--reconnect・--status を含む）も、起動のたびに sf-init.log を作り直します。sf-check.sh（ほかのコマンドや git のフックからも呼ばれる）と sf-prepush.sh（pre-push フック）だけは、実行のたびに追記されます。

コマンドの実行に失敗したときは、同じフォルダの error.log にも、失敗したコマンドと、その出力が追記されます（作り直されません）。force-* の sf-tools/logs/ は、git の対象外です。

作業フォルダの構成

sf-job.sh と sf-init.sh を実行する場所が、作業フォルダです。場所は任意です（おすすめ: ~/sf のような、短い名前のフォルダ）。admin・force-* の中では、どちらも実行できません。先に、管理者が sf-init.sh でリポジトリを作ります（admin/ ができます）。開発者は、そのあとで、sf-job.sh で、作業ごとのジョブフォルダを作ります。

{作業フォルダ}/
├── admin/                          ← sf-init.sh が作る、管理者用のフォルダ（完了後も残す。保守に使う）
│   ├── force-XXXX/                 ← 管理者用のクローン（完了後は admin ブランチ）
│   ├── .sf-init-XXXX.env           ← 状態ファイル（Phase 2 が作る。セットアップが完了したら消える）
│   ├── .sf-init-XXXX.progress      ← 進捗（完了した Phase。完了したら消える）
│   └── .sf-init-XXXX.lock/         ← 実行中の排他（中に PID。終了時に消える。強制終了で残ったものは、次の起動が引き継ぐ）
└── {ジョブ名}/                     ← sf-job.sh が作るジョブフォルダ（同じ force-XXXX を、同時に複数開くための入れ物）
    └── force-XXXX/                 ← ブランチ {ジョブ名} のクローン（VS Code で開く単位）

プロジェクト（オーナーと XXXX）は、フォルダの名前ではなく、引数（--owner / --project）か、カレントの直下の */force-*/ にあるクローンの origin の URL から決まります（sf-job.sh）。

ホームフォルダには、次のものがあります。

  • ~/sf-tools/ … sf-tools 本体（下記）。~/sf-tools/logs/ に、一部のコマンドのログ（上記）
  • ~/.sf-jwt/force-XXXX/ … JWT 認証用の server.key・server.crt（sf-init.sh の Phase 10 が作る。--add-tier・--reconnect・sf-update-secret.sh が使う。sf-init.sh を実行した管理者の PC にだけある）
  • ~/.sf-tools-last-update … sf-upgrade.sh を最後に起動した時刻の印（sf-install.sh が、24 時間おきの起動の判定に使う）

force-* プロジェクトの構成

雛形のファイルは、sf-init.sh の Phase 3 が、sf-tools の templates/ からコピーします（.gitmessage と、sf-tools/release/ の中は、sf-install.sh が作ります）。★ は、sf-tools 独自のもの（または、sf-tools 用に設定したもの）で、それ以外は、sf project generate が作る標準の構成と同じものです。☆ は、git の対象外で、それぞれのクローンで作られるものです。

force-XXXX/
├── .forceignore
├── .gitattributes                       ★ 改行コードの設定
├── .gitignore
├── .prettierrc / .prettierignore
├── .github/
│   └── workflows/                       ★ CI/CD（5 種類）
│       ├── wf-release.yml               ★   リリース（PR のマージ後）
│       ├── wf-validate.yml              ★   デプロイ前検証（PR ごと。dry-run）
│       ├── wf-sequence.yml              ★   マージ順序の確認
│       ├── wf-propagate.yml             ★   ブランチの伝播（main → staging・develop）
│       └── wf-metasync.yml              ★   メタデータの自動同期（組織 → main）
├── .vscode/                             ★ 推奨設定・拡張機能・デバッグ設定
├── config/
│   └── project-scratch-def.json
├── .gitmessage                          ★ コミットメッセージの雛形（sf-init の Phase 4 で、sf-install.sh が templates/gitmessage から作る。
│                                            commit.template の設定は、管理者用のクローンだけ）
├── eslint.config.js
├── force-app/                           ← Salesforce のメタデータ本体
├── jest.config.js
├── package.json
├── README.md                            ★ プロジェクトの README の雛形
├── scripts/
├── sfdx-project.json                    ← 名前は、Phase 3 がリポジトリ名に置き換える
├── sf-tools/                            ★
│   ├── config/
│   │   ├── branches.txt                 ★   使うブランチ（段階）の一覧。並びが順序（main → staging → develop）
│   │   └── metadata.txt                 ★   メタデータの同期（sf-metasync.sh）で取得する種類
│   ├── release/
│   │   ├── .gitkeep                     ★
│   │   ├── branch_name.txt              ☆   現在のブランチ名（sf-install.sh が書く。main では作らない）
│   │   └── <ブランチ>/                   ★   作業用ブランチごと（sf-install.sh が作る。main では作らない）
│   │       ├── deploy-target.txt        ★     リリースの対象
│   │       └── remove-target.txt        ★     削除の対象
│   └── logs/                            ☆   各コマンドのログ・error.log
└── .git/hooks/                          ☆ pre-commit・pre-push（sf-hook.sh が ~/sf-tools/hooks/ からコピー）

sf-tools/release/<ブランチ>/ に、リリースのときに作られる package.xml・destructiveChanges.xml も、git の対象外です。書き方は、ターゲットファイルにあります。
