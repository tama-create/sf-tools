📋 コマンド一覧

sf-tools のコマンドの一覧です。コマンドは、すべて ~/sf-tools/bin/ にあります。どのコマンドも、--help（または -h。多くのコマンドは、1 つ目の引数のときだけ）を付けると、概要・オプション・処理の流れを表示します。文書にないオプションを付けると、「不明なオプションです」と表示して止まります（綴りの誤りに、気づけるようにするためです。ランチャーは、番号以外の引数を「引数には番号を指定してください」で止めます）。

ふだんは、ランチャーで足ります

開発者の毎日の操作は、sf-launcher.sh（ランチャー）のメニューから、番号を押すだけで進められます。sf-start.sh の最後に、自動で開きます（sf-job.sh も、最後に sf-start.sh を起動するため、そのまま開きます）。このページは、コマンドを直接打つときの、一覧です（ランチャーの使い方）。

一覧

「ランチャーのメニュー」の ○ は、sf-launcher.sh のメニューから選べるコマンドです（ランチャー）。VS Code のターミナルでは、sf-start.sh（[6] Start）と sf-restart.sh（[7] Restart）は、メニューに表示されません。🔑 は管理者専用（警告と確認が出る）、⚠️ は使うときに注意が必要なコマンドです（次の節）。

管理者が使うコマンド

詳しい説明は、管理者ガイドにあります。

コマンド用途

sf-init.sh --add-tier🔑 既存のプロジェクトに、段階（staging・develop）を足す

sf-init.sh --reconnect🔑 1 つの段階の、接続先の Salesforce 組織を付け替える

sf-update-secret.sh🔑 GitHub の Secrets / Variables を再登録する

管理者専用コマンドの安全ガード

🔑 のついたコマンドは管理者専用です。実行すると、最初に赤い警告ボックスが表示されて、続けてよいかを聞かれます。警告は、必ず確認とセットで、表示だけで先へ進むことはありません。まちがえて実行したときは、N か q で、止められます（Enter で進む確認でも、N / q で止まります）。

コマンド確認GitHub Actions 上（GITHUB_ACTIONS=true）gh のユーザーの確認
sf-init.sh（通常の実行）開始画面で「用意ができたら Enter を押してください」（Enter / Y で進む。N / q で中断）。--resume N（2 以上）/ --only N のときは「続行しますか？」（Y / N / q）省略しないする（確認のあと）
sf-init.sh --add-tier「続行しますか？」（Y / N / q）省略しないする
sf-init.sh --reconnectいまの接続を表示してから「付け替えますか？」（Y / N / q）省略しないする
sf-init.sh --verify実行内容を表示してから、Enter の確認（Enter / Y で進む。N / q で、何も変更せずに中断）。本番の組織（または種類を判定できない組織）を含むときは、文面で明示します。--plan は、表示だけで、確認を出しません。セットアップの最後のステップ（動作の確認）から呼ばれたときは、sf-init.sh 側で確認済みのため、警告・確認を出しません実行を拒否するする
sf-update-secret.sh「続行しますか？」（Y / N / q）警告・確認を省略して実行するする
sf-sync-wf.sh「続行しますか？」（Y / N / q）と、上書きの直前の確認。--check は、警告・確認を出しません（何も変更しません）。--remove は、削除の直前に、もう一度確認します省略しないしない
sf-typecheck.sh「続行しますか？」（Y / N / q）。-y で確認だけを省略できます（警告ボックスは表示します）。--list・--coverage も同じです実行を拒否する（--list・--coverage は実行できます。確認に答えられないため、-y を付けます）しない
sf-metasync.sh「続行しますか？」（Y / N / q）。main にプッシュする前にも、変更（またはコミット）の一覧を表示して、もう一度確認します警告・確認を省略して実行する（wf-metasync の通常の動き）しない
  • gh のユーザーの確認: gh でログインしているユーザーが、リポジトリのオーナーと同じかを確かめます（大文字・小文字は区別しません）。違っていれば、そこで止まります。ただし、オーナーが GitHub 組織（例: tamashimon-org）で、認証ユーザーがその組織の有効な管理者（admin・active）なら、そのまま続行します。組織の一般メンバーや、組織の情報を取得できない場合は中断します（gh auth switch で正しいアカウントに切り替えてから、もう一度実行してください）。gh から認証ユーザーを取得できないとき（ネットワークの障害など）は、確かめずに進みます。
  • 表で「しない」のコマンドと、sf-init.sh --status（読み取りのみ。警告・確認も出しません）、開発者向けのコマンド（sf-job.sh を含む）は、gh のユーザーを確かめません。リポジトリを読み書きする権限は、GitHub が確認します。
共有環境と本番の組織には、手元からリリースできません

sf-release.sh（sf-dryrun.sh を含む）と sf-deploy.sh は、GitHub Actions の外では、エイリアスが予約名（prod / staging / develop / main）の組織・本番の組織・種類を確認できない組織を、確認（Y/N/q）より前に拒否します（検証も含む）。共有環境へのリリースは、GitHub にコミットして、レビューを通し、GitHub Actions で行います。sf-typecheck.sh も、同じ組織を拒否します。詳しくは、sf-release.sh にあります。
